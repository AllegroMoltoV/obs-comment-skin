# 見た目の崩れの自動検査

実施日: 2026-11-10
対象の課題: obs-comment-skin-dxs.17

## 背景

それまでの確認は、UI Automation で読む欄の名前と値と、CDP で読む計算済みのスタイルの値だけで行っていた。文字の見切れや部品の重なりのような見た目の崩れは検知できなかった。依頼者の承認を得て、ユーザーテスト c2 の前に、要素の位置と大きさを数値で調べる検査を入れた。検査の途中で、依頼者もドックの崩れを 3 点指摘した。

## 作成したもの

| ファイル | 内容 |
| --- | --- |
| `tests/css-dump.cpp` | 検査で当てる CSS を書き出す `comment-skin-css-dump`。`max` は数値の項目をすべて最大、`min` はすべて最小にし、縁取り、時刻、名前の後の「:」、メッセージの背景を有効にする |
| `tools/layout-check/page-check.mjs` | チャットのページに CSS を注入し、メッセージの文字の要素について、行の高さと文字の大きさ、overflow で切り取る祖先からのはみ出し、要素の高さ、アイコンと本文の重なり、横のはみ出しを調べる |
| `tools/layout-check/dock-check.ps1` | ドックの区画をすべて開き、スクロールしながら、表示範囲の欄のドックの右端からのはみ出し、欄どうしの重なり、狭すぎる欄を調べる |

使い方は次のとおり。崩れがあれば終了コード 1 で終わる。

```
build_x64/RelWithDebInfo/comment-skin-css-dump.exe max > max.css
node tools/layout-check/page-check.mjs <CDP の webSocketDebuggerUrl> max.css
pwsh tools/layout-check/dock-check.ps1 -ProcessId <OBS の PID>
```

## 検証方法

ポータブル版 OBS 33.0.1 を `--remote-debugging-port=9222` で起動し、ドックで「ブラウザ」を選んだ。ページの検査は、見本と実物のページのそれぞれに、CSS なし、`max`、`min` の 3 つを当てた。実物のページのメッセージは配信者の発言 1 件だった。

検査が崩れを検知できることを確かめるため、行の高さを 5 px、アイコンの右の余白を -40 px、Super Chat の本文の枠の高さを 6 px にした CSS を見本に当てた。

## 検証結果

### 検査の確かめ

わざと崩した CSS では、行の高さの崩れ 5 件、アイコンと本文の重なり 5 件、祖先からのはみ出し 2 件の、計 12 件を検知した。

### 見つかった崩れと修正

| 対象 | 崩れ | 原因 | 修正 |
| --- | --- | --- | --- |
| 実物のページ、`max` | 名前の要素がメッセージの右端で切り取られた | 名前を包む `yt-live-chat-author-chip` が `inline-flex` で、空白の無い名前は折り返されない | 名前の大きさを指定したときに、包む部品に `max-width: 100%`、名前に `min-width: 0` と `overflow-wrap: anywhere` を当てる |
| 見本、`max` | Super Chat の名前と金額が枠の右端で切り取られた | 名前と金額の列が flex の子で、「¥500」のような空白の無い文字列が折り返されない | 名前か金額の大きさを指定したときに、列に `min-width: 0`、名前と金額に `overflow-wrap: anywhere` を当てる |
| ドック | 欄がドックの右端で切れた。依頼者もプルダウンの右端の見切れを指摘した | 中身の最小の幅が約 480 px あり、幅 342 px のドックに横のスクロールバーが出ていた | 長い項目名を欄の上に折り返す。プリセットのボタンを名前の欄の下の行に移す。横のスクロールを止め、ドックの最小の幅を中身の最小の幅に合わせる |
| ドック | 依頼者が、見本がスクロールバーにかぶると指摘した | 見本はブラウザーの部品で、独立したウィンドウとして描かれ、スクロール領域の中では表示範囲の外にはみ出して描かれる | 見本をスクロール領域の外のドックの上端に移した |
| ドック | 依頼者が、見本が見本であることが分からないと指摘した | 見出しが無かった | 見本の上に「見本 — 設定を変えるとすぐに変わります。実際のチャットには少し遅れて反映されます。」と表示する |

ドックの最小の幅は、閉じた区画と非表示の欄が大きさの計算に入らないため、すべての区画を一時的に開いて求めた。ログの値は 339 px だった。

### 修正の後の検査

| 対象 | CSS なし | `max` | `min` |
| --- | --- | --- | --- |
| 見本のページ | 16 要素、崩れ 0 件 | 21 要素、崩れ 0 件 | 21 要素、崩れ 0 件 |
| 実物のページ | 2 要素、崩れ 0 件 | 3 要素、崩れ 0 件 | 3 要素、崩れ 0 件 |

ドックの検査は、幅 342 px、高さ 896 px で、105 の欄を調べて崩れ 0 件だった。見本は上端の高さ 260 px の範囲にあり、スクロールバーはその下から始まっていた。

最初のドックの検査では、見本のページの中の文字の要素を欄として数え、別の欄の縦のスクロールバーを基準にしていたため、誤った重なりとはみ出しを多数書き出した。ブラウザーの中の要素を除き、最も背の高い縦のスクロールバーを基準にするよう直した。

## 確認していないこと

- ドックを最小の幅まで狭めたときと、342 px より広い幅での検査。
- 文字の色と背景の色が近いときの読みにくさ。位置と大きさでは判定できない。
- アニメーションの途中の状態。検査の CSS ではアニメーションを無効にした。
- 実物のページの Super Chat とメンバーシップの崩れ。実物のチャットに該当するメッセージが無かった。

## 考察

位置と大きさの検査は、文字が折り返されずに切り取られる崩れを見つけるのに効果的だったと考えています。見本と実物で崩れの出方が違ったため、両方を検査する必要があると考えています。
