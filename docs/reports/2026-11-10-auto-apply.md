# 設定の変更の自動の適用

実施日: 2026-11-10
対象の課題: obs-comment-skin-dxs.15

## 背景

ユーザーテスト c1 で、依頼者は、適用ボタンを押すまで反映されないことに直感的に戸惑ったと報告しました。依頼者は、配信中の調整は想定しないため、設定を変えたら自動で適用すると決めました。プレビューしながらサイズの釣り合いを調整できることを重く見た判断です。待ち時間については、操作してからしばらく反映されないのは使いづらいと指摘しました。

## 変更内容

- 適用ボタンを外した。設定を変えると、最後の変更から 150 ミリ秒後に自動で適用する。待ち時間は、文字の大きさの欄への入力のように、1 回の操作で起きる連続した変更をまとめるためだけに置いた。
- 適用は、変更したソースの保存済みの設定から CSS を作る。待ち時間の間に別のソースを選んでも、変更したソースへ適用される。
- 元に戻す操作の意味を変えた。プラグインが最初に書き換える前の `css` を記録し、元に戻すボタンでその `css` に戻して、設定を既定に戻す。自動の適用では設定を変えるたびに適用が起きるため、直前の 1 回だけを戻しても元の見た目へ戻れないためである。
- 元に戻す時点で待っている適用は、同じソースへのものなら捨て、別のソースへのものならその場で済ませる。
- 目印が壊れているときは、自動の適用のたびにダイアログを出さず、ドックに警告を表示する。
- シーンコレクションを片付けるイベントで、待っている適用を捨てる。

## 検証方法

ポータブル版 OBS 33.0.1 を `--remote-debugging-port=9222` で起動し、ドックを `.tmp/2026111007-uia-do.ps1` で操作した。反映までの時間は、文字の大きさの欄に値を入れる直前の時刻から、作り直されたページの `#message` の計算済みの `font-size` が新しい値になるまでを `.tmp/2026111008-cdp-wait-style.mjs` で測った。この計測には、UI Automation の呼び出しの時間と 150 ミリ秒の待ち時間が含まれる。対象は、依頼者の配信のチャットを表示する「ブラウザ」で、チャットのメッセージは 1 件だった。

## 検証結果

### 反映までの時間

| 回 | 値 | UI Automation の呼び出し | 反映までの時間 |
| --- | --- | --- | --- |
| 1 | 24 px | 測っていない | 852 ms |
| 2 | 32 px | 128 ms | 881 ms |
| 3 | 20 px | 49 ms | 788 ms |
| 4 | 28 px | 47 ms | 785 ms |

作り直されたページには、作り直す前と同じ 1 件のメッセージが表示されていた。

### 連続した適用

| 条件 | 適用のログの行数 | OBS の状態 | 最後の値の反映 |
| --- | --- | --- | --- |
| 300 ms の間隔で 20 回変更 | 20 行。約 360 ms 間隔 | プロセスが動き、応答していた | 39 px が反映された |
| 間隔を空けずに 20 回変更 | 1 行 | プロセスが動き、応答していた | 59 px が反映された |

OBS の終了時のログは `Number of memory leaks: 0` だった。ログには YouTube のページのスクリプトのエラーの行があるが、プラグインが適用する前のページの初回の読み込みでも出ている。

### 元に戻す操作

新しく作ったソース「YouTube チャット」で、文字の大きさを 24 px、30 px と変えて 2 回適用させた後、元に戻すボタンを押した。シーンコレクションの JSON の `css` は、既定の CSS `body { background-color: rgba(0, 0, 0, 0); margin: 0px auto; overflow: hidden; }` だけになった。ドックの文字の大きさは既定に戻り、元に戻すボタンは無効になった。

依頼者が c1 で使った「ブラウザ」では、元に戻すと、文字の大きさ 96 px の管理範囲が残った。この記録は、最後の適用の直前の `css` を記録していた旧い版が c1 の間に残したものである。確認の後、OBS を終了した状態で、シーンコレクションの JSON から「ブラウザ」の管理範囲を取り除いた。取り除く前の JSON は `.tmp/2026111009-scene-backup.json` に控えた。取り除いた後の JSON と控えを、`css` を除いて `jq -S` で整えて比べ、一致することを確かめた。

## 確認していないこと

- メッセージの多い配信での反映までの時間と、作り直した後に表示されるメッセージの件数。今回のチャットのメッセージは 1 件だった。
- 文字の大きさの欄の矢印を押し続けたときの適用の回数。UI Automation では値を直接入れたため、矢印の操作による変更の間隔は測っていない。
- 目印が壊れているときの警告の表示。

## 考察

反映までの時間のうち、待ち時間と UI Automation の呼び出しを除いた約 0.6 秒が、ページの作り直しにかかった時間だと考えています。この時間はプラグインからは縮められないため、即座に見比べたい用途には、課題 .16 で検証するドックの見本のプレビューが必要だと考えています。

300 ms の間隔では、前のページの読み込みが終わる前に次の適用が始まっていたと推測します。それでも OBS が応答を続け、最後の値が反映されたため、短い間隔の連続した適用は安定して扱えると考えています。ただし、確かめたのは 20 回の連続した適用の 2 つの条件だけです。
